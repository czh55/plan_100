# 数据分析型汇报材料组织

本项目 pipeline：`data-report-org`  
来源：自己定义

## 三条硬原则（不可改写）

1. 通俗但不删数据
2. 没有新定义词汇，写给第一次阅读的人
3. 顺着读者的疑问组织结构，而不是按照资料本身的结构

## 何时启用

有数据要交代、读者多半第一次看、目标是「读完能做判断」——不是展示你读过多少资料。

## 步骤

### 1. 先写读者疑问（禁止先写目录）

| 顺序 | 读者心里的问题 | 必须交出的东西 |
|------|----------------|----------------|
| Q1 | 这件事到底在说什么？为什么现在要看？ | 一句话结论 + 时间/范围 |
| Q2 | 用什么尺子量的？尺子可靠吗？ | 口径、样本、单位、缺口（原样给出） |
| Q3 | 主要发现是什么？哪几条够我决策？ | 3±1 条发现，每条带数 |
| Q4 | 和我以为的有何不同？差异从哪来？ | 对比/拆解表，保留全部分项 |
| Q5 | 不确定在哪？ | 置信边界、缺失、反例 |
| Q6 | 下一步建议是什么？依据是哪条数？ | 建议 ↔ 数据锚点一一对应 |

闸门：Q1–Q6 写不全，不开始正文。

### 2. 按疑问装填（通俗，不删数）

对每个 Qi：

1. 先一句人话（无术语、无新造词）
2. 紧跟完整数据块（表/全部分项/原单位；可进附录，但正文必须能指到）
3. 一句「所以这意味着…」（仍绑在数上）

禁止：合并掉分项、只报「显著上升」不报基期/绝对值、用未解释的「综合指数」代替算法。

### 3. 词表消毒

只允许日常汉语，或读者岗位上已经默认会的词。  
候选新词三选一：删掉 / 换成旧词 / 改成一句描述（禁止「我们把 A÷B 叫某某率」式命名）。

闸门：没看过资料的人读标题+小标题，凡需要口头解释的词一律改掉。

### 4. 按疑问重排

- 正文顺序 = Q1→Q6
- 资料原章节只当证据柜，不当大纲
- 映射不上的进附录或删结构（删的是结构，不是数据）

### 5. 交付三检

| 检 | 失败信号 | 处置 |
|----|----------|------|
| 通俗不删数 | 有结论无数，或有数缺分项/口径 | 补全或标「待补数」 |
| 无新词 | 小标题出现需定义的词 | 改写 |
| 疑问序 | 章节跟着资料/部门走 | 按 Q1–Q6 重排 |

## 一页骨架

```text
1. 现在要判断什么（Q1）
2. 我们实际量到了什么、没量到什么（Q2 + 全表）
3. 三条发现（人话 → 完整数 → 含义）（Q3–Q4）
4. 别过度相信的地方（Q5）
5. 建议与所依据的数（Q6）
附录：原始分项 / 口径说明
```
